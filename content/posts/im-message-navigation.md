点击引用消息跳回原文，表面上只是一次滚动。真正要解决的却是三个不同问题：目标有没有加载、有没有对应的组件、组件现在在哪里。

项目通过消息 UID 在已加载数据里查找，找到后读取 GlobalKey 的 context，再调用 `Scrollable.ensureVisible`。如果没找到，则继续加载历史。这条路径把目标识别和滚动连接了起来，但有两个细节值得调整。

第一，索引 0 也是合法结果。不能用“不是 -1 并且不是 0”表示找到，否则第一条消息会被当作缺失。

第二，数据存在并不代表组件已经挂载。长列表按需构建时，远处消息的 context 可能仍为空。[ensureVisible](https://api.flutter.dev/flutter/widgets/Scrollable/ensureVisible.html) 需要已有 context，它不会替你获取消息或构建任意远处的行。

### 把定位拆成三步

```text
按消息 UID 查本地数据
    不存在：优先按消息 ID / 时间窗口查询；否则有上限地补历史
目标已经进入数据集
    按索引定位工具让它进入可构建范围
目标组件已布局
    精确对齐到视口，再做一次短暂高亮
```

这三个步骤应该有一个共同的任务编号。用户连续点了两条引用时，只允许最后一次任务改变滚动位置；退出会话后，之前的定位也应失效。

如果 SDK 没有按消息定位的查询能力，只能逐页补历史，就要限制页数、总耗时，并检查游标是否推进。网络失败与“历史已耗尽仍未找到”应显示不同提示，不要一律说消息不存在。

### 高亮只是一种临时展示状态

可以在页面状态里保存 `highlightedMessageId`，而不是修改消息正文。定位成功后设置它，短暂显示强调背景，再清除。新的定位任务到来时，旧清除回调也需要校验编号，避免把新高亮提前关掉。

稳定消息标识同时服务于查找、去重和 key。GlobalKey 主要是获取已挂载组件的上下文，不适合承担消息的业务身份。

这项功能最容易漏掉的场景，是目标恰好在第一条、目标已加载却还没构建，以及用户连续点不同引用。把这些路径走通，比单纯让 `animateTo` 更平滑更重要。
